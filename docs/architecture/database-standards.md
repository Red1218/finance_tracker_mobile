# Finance Tracker v2 — Database Standards

## Purpose

This document defines the canonical database standards for Finance Tracker v2.

Every migration, table, function, trigger, index, and policy MUST follow these standards.

---

# Naming

## Tables

- snake_case
- plural nouns

Examples:

- categories
- expenses
- budgets

## Columns

- snake_case
- singular names

Examples

- user_id
- category_id
- created_at

---

# Primary Keys

Every business table uses UUID primary keys generated by PostgreSQL.

```sql
id UUID PRIMARY KEY DEFAULT gen_random_uuid()
```

---

# Audit Columns

Every business table contains:

```sql
created_at TIMESTAMPTZ NOT NULL DEFAULT now()

updated_at TIMESTAMPTZ NOT NULL DEFAULT now()

deleted_at TIMESTAMPTZ NULL
```

---

# User Ownership

Every business table contains:

```sql
user_id UUID NOT NULL
REFERENCES auth.users(id)
```

---

# Foreign Keys

Foreign keys must always use explicit constraints.

Example:

```sql
category_id UUID NOT NULL
REFERENCES categories(id)
```

---

# Soft Delete

Business tables are never physically deleted.

Soft delete is implemented using:

```sql
deleted_at TIMESTAMPTZ NULL
```

---

# Constraints

Business rules should exist in the database whenever possible.

Examples:

- CHECK constraints
- UNIQUE constraints
- NOT NULL constraints

---

# Indexes

Indexes are required for:

- every foreign key
- user_id
- deleted_at
- frequently queried columns

---

# Row Level Security

RLS must be enabled on every user-owned table.

Policies must enforce:

- Users can only access their own data.
- Service role bypasses RLS.

---

# Triggers

A shared trigger updates updated_at automatically.

Applications must never manually update updated_at.

---

# Migrations

Migrations are immutable.

Never edit an applied migration.

Instead:

- Create a new migration.
- Apply the change.
- Commit the migration.

---

# Version Control

Database schema is managed exclusively through migrations.

Never create or modify production tables manually in the Supabase dashboard.

---

# Future Compatibility

These standards are designed for:

- Mobile
- Web
- Desktop
- Multi-user architecture
- Enterprise deployment
